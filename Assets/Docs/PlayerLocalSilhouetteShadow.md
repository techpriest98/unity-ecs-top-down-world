# Source-separated local light near the player (experimental)

STATUS: temporarily paused after the dark-radius regression. Runtime LocalLightingReplacementEnabled is false and shader PLAYER_LOCAL_LIGHT_REPLACEMENT is 0. Original voxel local RGB/normal response is active; no local silhouette/grid updates or local count uploads occur. Sun shadows, sun and skylight remain active as before. Existing inspector selections and experimental code are retained. Both gates must be deliberately restored together when debugging resumes; the separate world-visibility bypass is still present.

## Current implementation (supersedes the historical pilot below)

Block normals are now active in the validated local-light bundle. Every source uses its own world-space receiver-to-light direction and the decoded/overlay-composited world normal. Local Light Normal Strength controls the same bounded perturbation used by legacy voxel light: clamp(1 + strength * (dot(normal,L)-dot(reference,L)), 0.35, 1.65). Strength zero or an unchanged reference normal preserves previous brightness. A coincident source has a finite neutral response. Top reference is the existing normalized (0,1,1) atlas baseline, sides use (0,0,1) transformed by GetWorldNormal. Geometric normals still determine the visibility-ray bias, never the painted normal. Normal response multiplies each source once before summation; sun/skylight, cached visibility, precise edges and player silhouette projection are unchanged.

Validated bundle control: the ChunkRenderer object in Scenes/WorldScene.unity now has LocalLightingDebug with a single Enable Local Lighting checkbox (on). It replaces the five test checkboxes previously on ChunkProceduralRenderer. On enables multiple additive sources, player silhouette shadows, cached wall visibility and precise edge refinement together. Off/component-disabled/missing restores legacy voxel local lighting; sun/skylight and sun shadows retain independent behaviour. Runtime GPU resource ownership remains in the ECS presentation system so the shared sun/player silhouette is still rendered only once. Existing shadow strength/shared offset controls are preserved on the renderer. No old broken replacement path is re-enabled. Earlier per-option instructions below are historical.

Held-source wall protection: PlayerEquipmentLightSystem now sweeps the authored emitter segment from the player's horizontal center (at the emitter height, clamped inside the player's height) to the desired point. It resolves lower/upper split materials and stops 0.04 world units before the first solid box, including a target exactly on a wall boundary. Water is transparent; missing geometry fails closed to the player's interior reference. Malformed offsets longer than eight world units also fail closed to bound the small CPU scan. This updates only DynamicLightWorldPosition: sprite ordering, saved anchors, art and ground items remain unchanged. All lighting paths consume the same adjusted source position. PlayerHeldLightWallChecks runs the actual clamp with synthetic block-access fixtures; check near-wall behaviour/camera directions and FPS in Unity.

Optional edge refinement: enable Test Local Light Precise Edges together with block occlusion. A second compute dispatch classifies cells with any differently visible neighbour in a 3x3x3 neighbourhood. Classification is cached/invalidation-shared with visibility. The terrain shader performs an exact world-space DDA only for these flagged cells; all other cells keep the coarse cached lookup. Toggle default is off and can be compared live without changing source positions. One extra 500 KiB edge buffer is used; all resources release on destruction. This may recover straight boundaries near represented edges, but is not identical to tracing everywhere: thin occluders missed by all coarse samples can remain missed. GPU cost depends on screen coverage of flagged cells, especially walls/ground where vertical neighbours differ; do not assume it will retain baseline FPS. Compare the same camera and lights with only this toggle changing, standing and moving.

Cache invalidation fix: streamed chunks now have ChunkGeometryRevision, incremented after generation (including pool reuse) and every accepted block edit, including underground edits that leave the minimap surface unchanged. Normal chunks hash this explicit revision plus entity identity, not ECS buffer-access versions. Legacy/unversioned chunks retain conservative buffer-version fallback. SkyLightSystem reads BlockData/SplitCellData through read-only lookups rather than writable query buffers. Thus routine sky/projection queries no longer invalidate normal chunk visibility caches. Grid origin, loading/unloading and genuine block edits still invalidate; source position/radius still invalidates that source. Zero-source/overflow early returns remain before grid/compute work. Profiler CPU markers PlayerLocalLight.GridRebuild and PlayerLocalLight.VisibilityDispatch expose rebuild/submission frequency (not GPU execution time). Re-enter Play Mode after import so streamed chunk archetypes include the new revision. Actual FPS recovery still requires user measurement.

Performance revision: Test Local Light Block Occlusion now uses Resources/PlayerLocalVisibility.compute and a cached visibility buffer, not per-fragment DDA. Each source has 20x40x20 uint cells (1 world unit X/Z, 0.5 Y; a margin around radius-eight lights). Only changed source position/radius or occupancy version dispatches its mask; color changes do not retrace geometry. Grid-origin/content changes invalidate all active masks. The fragment shader performs one indexed visibility read per contributing source. Masks total 500 KiB plus the existing 500 KiB occupancy buffer. No CPU readback, texture atlas or world-projection rebuild is introduced. Moving sources still dispatch bounded compute work; stationary lights reuse their masks. Unsupported compute/missing resource falls back to the unoccluded diagnostic. Resources release on system destruction.

This is deliberately lower-resolution than per-pixel rays: wall shadow boundaries can be stepped, and subcell blockers/receivers can be over- or under-occluded. Physical light position/distance attenuation and player silhouette shadows remain continuous. Compare FPS while standing/walking and with static versus held lights; performance recovery is not claimed without in-game measurements. The previous per-fragment implementation description below is historical; its DDA function remains dormant in the old disabled path.

Optional world-block visibility: Test Local Light Block Occlusion (default off) runs bounded GPU DDA per contributing source/pixel against the cached half-height occupancy buffer. It uses the verified diagnostic receiver/source WORLD coordinates directly, not the old vertex visibility/counter path. Rays start 0.02 world units outward along the receiving face normal to avoid floor self-occlusion. The grid preparation is shared, but does not enable the old source-separated lighting experiment or upload its counter. Missing chunks block rays, water transmits; source-cell exemption is retained for mounted emitters. Only this toggle prepares/refreshes the grid for the diagnostic. Disabling it immediately restores the user-verified lighting/shadows without world blocking. This can cost substantially more GPU time than distance-only/silhouette shading: compare FPS and camera turns, standing/walking, half blocks and opposite sides of a wall. No frame-rate claim is made. PlayerLocalBlockRayChecks executes extracted production DDA arithmetic against synthetic floor/full/half/negative-origin fixtures; Unity visuals and resource binding still require manual validation.

Optional diagnostic silhouette shadows: enable Test Local Light Shadows alongside Test Single Local Light (and optionally Test Multiple Local Lights). Player Local Shadow Strength sets transmission and shared Player Sun Shadow Offset sets the caster anchor. Each contributing light's segment tests the current silhouette before its RGB is added; floors and wall receivers share this path. The mask is generated even at night/with sun shadows disabled. The diagnostic shadow strength remains zero until a valid current-frame mask is published and resets on update/stop/destroy. Disabling this toggle skips silhouette samples and returns to the verified distance-only diagnostic. World visibility, normals and the previous grid/counter path remain disabled. Compare opposite torches, moving/idle, pickup/drop, four camera directions and FPS; in-scene verification is still required.

Multi-source diagnostic: keep Test Single Local Light enabled and also enable Test Multiple Local Lights. The same verified world-position/distance path sums up to eight enabled nearby sources. Position/color arrays are cleared every frame so removed sources leave no stale light. Zero-radius slots are skipped; no integer counter, masks, normals or occupancy are involved. More than eight candidates or no candidates restores legacy lighting for that frame. Disable only Test Multiple Local Lights to compare with stable single-source selection; disable Test Single Local Light to restore normal voxel lighting. Source contributions are summed before final ambient/sun/local saturation, so overlapping sources can become brighter. This remains a bounded diagnostic without wall occlusion.

Isolated diagnostic: ChunkProceduralRenderer / Local Light Diagnostic / Test Single Local Light (off by default). In Play Mode enable it with one torch equipped and no other nearby emitters for an unambiguous comparison. One enabled nearby emitter is selected and retained until disabled/out of range; its actual world position/color/radius updates every presentation frame, independently of projection uploads. Within radius seven it replaces only local voxel RGB with distance attenuation, blending to legacy at eight. No normal response, silhouette masks, world visibility, grid rebuilding or integer light counters are used in this test. Sun/skylight remain unchanged. Compare standing, walking, turning and returning to idle; disable the checkbox to immediately restore the working voxel path. This is deliberately not production lighting and can illuminate through walls.

Near the player, enabled DynamicLightSource / DynamicLightWorldPosition entities are gathered directly, independently of head/feet visibility. Each source contributes RGB only after its own distance attenuation, normal response, block visibility and silhouette occlusion. Contributions are added, not maximum-combined or multiplied by a shadow ratio. Both real tops and wall faces receive local shadows; cut caps are excluded. Ambient and sun remain separate; sun retains its top-only receiver limits.

The replacement covers radius/relative height seven, fades to legacy voxel light from seven to eight, and is clipped beyond eight. At most eight sources intersecting this region are supported. More sources cause complete fallback to legacy lighting, not loss of unselected illumination. The rest of the world still uses maximum-RGB voxel light. Light anchors, sprite sorting and atlases are unchanged. The shared caster offset is preserved; old radius padding is no longer used.

A cached 40x80x40 uint occupancy buffer (500 KiB) respects half-height/split blocks, treats water as transparent and missing chunks as opaque. It rebuilds on four-unit snapped-grid moves, relevant chunk identities or block/split change versions, not every player animation frame. GPU DDA world visibility runs per nearby terrain vertex and interpolates across tiles; this is an approximation and may soften/leak block visibility at tile boundaries. The source's own cell is skipped for mounted emitters. Per-source silhouette tests remain per fragment and use the same single 64x128 mask draw. No player-driven world voxel-light/chunk rebuild is added; terrain record stride remains 48 bytes.

Play Mode validation is required for two opposing lights, wall receivers, half blocks, camera rotation, boundary blending and moving-player FPS/grid-refresh spikes. A flat billboard still cannot cast anatomical 3D shadows, and coplanar rays cannot project it. Strength below one intentionally transmits part of the blocked light.

## Historical pilot (replaced)

ChunkProceduralRenderer has **Player Local Light Shadows** and **Player Local Shadow Strength** (default on / 0.8), independent of the sun-shadow checkbox. The existing Player Sun Shadow Offset translates the common receiver anchor for both types. No atlas rebuild; re-enter Play Mode after script/shader import.

Reuses the existing 64x128 alpha silhouette and one GPU mask draw, including active body, arms and held items. Sources come from PlayerNormalPointLight (the existing up-to-eight closest visible emitters selected with head/feet visibility tests). Rank by estimated energy at player feet; only the first four perform silhouette shadow sampling. All eight participate in known-source fill. Ground items, held torches/staff and other emitters already present in that buffer participate automatically. Works at night even if the sun-shadow feature is off.

Each ground receiver casts a segment toward the point light and intersects the player billboard plane. Only an intersection strictly between source and receiver can cast shadow. The perspective intersection naturally changes silhouette magnification with light distance/height. Point attenuation/radius is respected. Parallel rays, lights exactly on the caster plane, out-of-bounds silhouettes and off-height floors are rejected safely.

Terrain RGB local light already stores component-wise maxima rather than source-separated contributions. This pilot models the selected emitters' unshadowed and shadowed maxima and applies their per-channel ratio to existing local RGB. It does not darken ambient or sun, does not change original falloff/normal-response when there is no shadow hit, and lets other known unblocked lights fill the shadow. This is an approximation: unselected sources, voxel visibility at each receiver and corner-interpolated light do not have individually recoverable contributions. Brightness with many overlapping lights needs in-game review.

Shares the sun pilot receiver limits: real visible Top surfaces within 0.55 height of player feet and radius 8; no side walls, lower levels, water or cut caps; no self-shadow. A floor-height torch cannot cast the entire upper body onto a horizontal floor because it is below that body geometry; mainly low portions of the silhouette intersect such rays. Sources on the billboard plane may yield no projected floor shadow. This is a flat-sprite shadow, not 3D anatomy or volumetric occlusion.

Globals reset when systems stop/destroy and before each update, so stale lights do not remain after sources disappear. Source lights and authored anchors are not modified. No per-frame managed arrays or per-source render targets are allocated; shader cost is bounded by eight contribution evaluations and at most four nearby silhouette samples. Profile actual FPS before enabling permanently.

Checks: runtime assembly compilation; terrain HLSL base/clipping/debug compilation; PlayerSunShadowChecks point-light inverse projection at two source sides, magnification, and invalid/parallel segments alongside sun projection regression. Scene visuals, mask orientation and multiple-light behavior still need Play Mode validation.
